## 2025-03-07 - Missing Rate Limiting on Custom Auth Routes
**Vulnerability:** The custom API endpoints for authentication (`/api/auth/pin/login/route.ts` and `/api/auth/admin/login/route.ts`) were fully exposed without any request rate limiting. This meant an attacker could infinitely spam the endpoint to guess credentials.
**Learning:** This is particularly dangerous for the PIN-based authentication. The `employee` PIN authentication is explicitly described as a 4-6 digit code, making it trivial to brute-force if there's no limit on the number of attempts. Furthermore, the PIN authentication performs an O(N) database lookup across all active employees per attempt, meaning an automated brute force attack would also lead to an immediate DoS.
**Prevention:** Always implement an explicit rate limiting mechanism for any authentication routes, especially when dealing with custom Next.js API route handlers instead of established Auth frameworks (like NextAuth). Implement rate limiting via an in-memory solution or Redis for multi-instance environments.
