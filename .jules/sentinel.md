## 2024-05-18 - [Missing Authorization Check Before Prisma Mutation]
**Vulnerability:** Insecure Direct Object Reference (IDOR) on operational area PATCH and DELETE API routes. The endpoints executed `prisma.update` directly using the provided `id` parameter without verifying if the operational area belonged to the authenticated user's `company_id`.
**Learning:** Prisma's `update` and `delete` operations inherently require unique identifiers (like primary keys) in the `where` clause. Because of this, it's not possible to natively add non-unique conditions like `company_id` to the `where` block of these specific mutation queries to enforce tenant isolation.
**Prevention:** Always perform a separate preliminary authorization check using `prisma.findFirst` with the unique `id` and the required boundary constraint (e.g., `company_id`) before executing any mutation methods. If `findFirst` returns null, return an immediate 404/403 HTTP response to block unauthorized mutations.
