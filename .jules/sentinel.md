## 2024-05-14 - IDOR Vulnerabilities in Task API Endpoints
**Vulnerability:** Several API endpoints related to Tasks (`/api/operations/tasks/[taskId]`, `/api/my-tasks/[id]/complete`, `/api/my-tasks/[id]/checklist/[itemId]`) suffered from Insecure Direct Object Reference (IDOR). They used `findFirstOrThrow` or `findUniqueOrThrow` to look up entities purely by their ID without verifying the `company_id` and the user it was `assigned_to`.
**Learning:** Due to the multi-tenant nature of the system (`company_id`) and the role-based scoping (employees viewing only their `assigned_to` tasks), queries cannot rely on primary key lookups alone. Every Prisma query for operational items must filter by the authenticated session's `company_id` and applicable user ID context.
**Prevention:** Always verify `company_id` in database queries in multi-tenant contexts. For user-specific resources, also query by the owner's ID (`assigned_to: auth.employee.id`). Replace `findUnique` with `findFirst` in Prisma when multi-column unique constraints are not available to enforce this isolation.
