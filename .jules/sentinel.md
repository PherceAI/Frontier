## 2024-06-09 - [Fix IDOR in Operational Area Endpoints]
**Vulnerability:** IDOR vulnerability in operational area endpoints (`PATCH` and `DELETE` at `frontend/src/app/api/config/areas/[id]/route.ts`) where users could modify or delete areas belonging to other companies by guessing the ID, and `GET` using `findFirstOrThrow` leading to HTTP 500 when accessing unauthorized or missing areas.
**Learning:** Prisma's `update` and `delete` methods do not natively support composite keys enforcing tenant ownership (e.g. `company_id`) alongside primary keys out-of-the-box in `where`. If we don't first verify ownership, an IDOR occurs. Similarly, `findFirstOrThrow` should be avoided for multi-tenant ownership checks since a failure causes an uncaught Prisma error yielding a 500 status rather than a 404.
**Prevention:** Always verify `company_id` using `prisma.findFirst` before executing `update` or `delete` in configuration endpoints. Return a structured 404 error instead of throwing exceptions.
