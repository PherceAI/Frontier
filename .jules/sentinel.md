## 2024-05-08 - [Add Rate Limiter to Authentication Endpoints]
**Vulnerability:** The authentication endpoints (`/api/auth/pin/login` and `/api/auth/admin/login`) lacked rate limiting, making them vulnerable to brute-force and credential stuffing attacks. The employee PIN system was particularly at risk due to its short 4-6 digit space and O(N) lookup.
**Learning:** Next.js App Router API routes handle IPs differently; standard Express techniques don't directly map. Additionally, simple in-memory `Map` based limiters are vulnerable to memory exhaustion (OOM DoS) if an attacker spoofs millions of random IPs unless an LRU eviction strategy is explicitly implemented to cap the cache size. Furthermore, custom rate limiters must include test environment bypasses (`process.env.NODE_ENV === 'test'`) or they will break the integration test suite by blocking rapid, repeated API calls from the test runner.
**Prevention:** Use an LRU-based approach for custom in-memory rate limiting to bound memory usage. Read the IP from `x-forwarded-for` with a fallback, taking care to extract only the first client IP in the chain to handle proxies correctly. Always include test environment overrides.
