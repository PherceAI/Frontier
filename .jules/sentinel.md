## 2024-06-27 - IDOR in Nested Resources (Task Checklist Items)
**Vulnerability:** Insecure Direct Object Reference (IDOR) vulnerabilities existed in `my-tasks/[id]/checklist/[itemId]/route.ts` and `operations/tasks/[taskId]/items/[itemId]/route.ts`. The endpoints updated checklist items by only verifying the `itemId` primary key without enforcing that the item actually belonged to the `taskId` specified in the URL or that the parent task belonged to the user's tenant (`company_id`).
**Learning:** When dealing with nested resources (like `tasks/1/items/5`), it is insufficient to only use `findUniqueOrThrow` with the primary key. You must explicitly verify the relationship between the parent and child resources in the query, as well as enforce tenant isolation at the parent level.
**Prevention:** Always use `prisma.findFirst` to enforce both the parent-child relationship (e.g., `task_id: taskId`) and tenant ownership (e.g., `task: { company_id: ... }`) before performing a mutation. Return a 404 response instead of throwing a 500 error to avoid unhandled exceptions and leaking internal error details.
