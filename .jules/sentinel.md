## 2024-03-13 - [HIGH] Add IP-based Rate Limiting to Authentication Endpoints
**Vulnerability:** Missing rate limiting on sensitive authentication endpoints (`/api/auth/pin/login` and `/api/auth/admin/login`). This allows for unlimited brute-force attempts and credential stuffing attacks against user and employee accounts.
**Learning:** In a Next.js App Router environment, relying solely on `request.ip` for client identification is often insufficient and can lead to IP spoofing bypasses if not behind a proxy that explicitly sets it. Parsing `x-forwarded-for` is necessary. Additionally, simple in-memory `Map` based rate limiters are susceptible to Out-Of-Memory (OOM) DoS attacks if an attacker spoofs millions of unique IPs. A size limit and cleanup mechanism must be implemented, though an LRU cache is ideal to prevent cache-flushing bypasses when the map fills up. Furthermore, sharing the same IP key across different endpoints groups their rate limits together; prefixing the cache key with the endpoint path (e.g., `[path]:[ip]`) allows for independent rate limiting per route.
**Prevention:** Always implement rate limiting on authentication endpoints. Use robust IP resolution (parsing `x-forwarded-for` safely). When using in-memory stores, always implement size limits and eviction policies (like LRU) to prevent memory exhaustion and cache-flushing bypasses. Scope rate limit cache keys by endpoint to avoid unintended shared limits.
