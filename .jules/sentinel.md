## 2024-03-20 - [Add Rate Limiting to Auth Endpoints]
**Vulnerability:** Both the Admin and PIN login endpoints were completely unprotected from brute-force and DoS attacks. In particular, the PIN login involves an O(N) database lookup over all employees, exacerbating the impact of any repeated requests.
**Learning:** In Next.js App Router (especially Next 15+), `NextRequest.ip` is often removed/unavailable, so relying on the `x-forwarded-for` header is crucial for identifying clients. Custom in-memory rate limiters must implement a maximum size constraint and an LRU eviction strategy; otherwise, spoofed IP attacks can cause the Map to grow indefinitely, leading to an Out-Of-Memory (OOM) crash.
**Prevention:** Always implement standard rate-limiting (e.g., 5 requests/minute) on authentication routes. Use an LRU eviction pattern for in-memory Map implementations. Add bypass checks for testing environments (like `vitest`) so integration tests can repeatedly hit endpoints without failing.
