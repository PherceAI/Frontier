## 2024-05-02 - [CRITICAL] Fix IDOR in Employee Task and Checklist Endpoints
**Vulnerability:** Found Insecure Direct Object Reference (IDOR) vulnerabilities in the `/api/my-tasks/[id]/complete` and `/api/my-tasks/[id]/checklist/[itemId]` endpoints where Prisma's `findUniqueOrThrow` or direct `update` was being executed using only the provided `id` parameter from the URL, without confirming that the task or checklist item actually belonged to the authenticated employee calling the endpoint.
**Learning:** In a multi-tenant environment built with Next.js App Router and Prisma, resolving parameters directly to database lookups without appending user context in the `where` clause creates IDOR vulnerabilities. Specifically for nested resources like checklist items, the relationship hierarchy (item -> task -> employee -> company) must be validated.
**Prevention:** Always use `findFirstOrThrow` rather than `findUniqueOrThrow`, and include the expected relation constraints (e.g., `company_id: user.company_id`, `assigned_to: user.employee.id`, `task_id: taskId`) in the `where` filter to explicitly verify the resource belongs to the current user's security scope before performing mutation actions like `update` or `delete`.
