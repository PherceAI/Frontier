## 2025-03-01 - Missing Rate Limiting on Authentication Endpoints
**Vulnerability:** The PIN login endpoint (`/api/auth/pin/login/route.ts`) and Admin login endpoint (`/api/auth/admin/login/route.ts`) were missing rate limiting. This allowed brute-forcing of credentials (especially PINs, which are short and easy to brute force) and made the server vulnerable to DoS through intensive bcrypt operations. In fact, the PIN login specifically fetches ALL employees and performs a bcrypt check loop for a matching PIN, making a brute force attempt extremely computationally expensive per request (`O(N)`).
**Learning:** Even internal hotel management applications are susceptible to automated brute-forcing. Without rate limiting, the N-size query + bcrypt iterations issue becomes a critical vulnerability that an attacker can use to completely stall the server and extract valid employee PINs simultaneously.
**Prevention:** Implement strict IP-based rate limiting on all authentication endpoints, and prioritize architectural changes to O(1) database lookups for credentials instead of iterating over entire collections.
