## 2024-04-26 - IDOR Vulnerabilities in Nested Prisma Mutations
**Vulnerability:** Insecure Direct Object Reference (IDOR) vulnerabilities were present in multiple API routes dealing with nested resources, specifically task endpoints (e.g., `my-tasks/[id]/checklist/[itemId]/route.ts` and `operations/tasks/[taskId]/items/[itemId]/route.ts`).
**Learning:** `prisma.update` and `prisma.findUniqueOrThrow` queries were directly using IDs passed from user input (`itemId`, `taskId`) without first validating that the resource actually belonged to the currently authenticated user's `company_id` or that the nested resource (`itemId`) actually belonged to the parent resource (`taskId`).
**Prevention:** Always explicitly enforce relationships in database queries. When updating a nested resource, first query the parent resource using `prisma.findFirstOrThrow` combining the requested `id` AND the tenant identifier (`company_id` or `assigned_to` from the auth session). Then, explicitly verify the nested resource's foreign key (`task_id`) matches the parent resource.
