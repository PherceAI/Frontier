## 2024-05-24 - Rate Limiting on Login Endpoints
**Vulnerability:** Missing rate limiting on sensitive authentication APIs (`/api/auth/pin/login` and `/api/auth/admin/login`), exposing the application to brute-force and credential stuffing attacks. The risk was particularly high for the PIN login route, which used 4-6 digit numeric PINs.
**Learning:** Due to Next.js App Router environment limitations where `NextRequest.ip` might be `undefined`, the secure IP resolution logic had to manually parse the `x-forwarded-for` header (e.g., `forwardedFor.split(',')[0].trim()`) with a fallback to avoid IP spoofing bypasses. Additionally, the in-memory Map structure for tracking limits had to explicitly employ LRU cache eviction logic (bounding size) to prevent potential OOM global lockout DoS attacks from spoofed IPs.
**Prevention:** In the future, enforce standard LRU capacity-bounded rate-limit middleware systematically for all custom authentication routes rather than ad-hoc implementations, ensuring IPs are parsed correctly from `x-forwarded-for`.
