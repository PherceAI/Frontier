## 2024-03-14 - Prevent OOM DoS in In-Memory Rate Limiters
**Vulnerability:** The lack of a size limit in an in-memory `Map` used for rate limiting IPs can be exploited via an Out-Of-Memory (OOM) Denial of Service (DoS) attack. An attacker can send requests with spoofed `X-Forwarded-For` headers, forcing the application to store an unbounded number of entries until it crashes. Additionally, a naive "fail-secure" block when the map is full creates a secondary global DoS vulnerability.
**Learning:** When using custom rate limiting utilities (like the one implemented for auth endpoints), relying solely on time-based cleanup is insufficient against active spoofing attacks. Blocking new IPs when full allows trivial global lockouts. `x-forwarded-for` can also be easily spoofed.
**Prevention:** Always enforce a maximum size limit (`maxMapSize`) on the underlying data structure and implement an LRU (Least Recently Used) eviction policy (like deleting `store.keys().next().value` from a `Map`) to preserve system availability without causing global lockouts.
